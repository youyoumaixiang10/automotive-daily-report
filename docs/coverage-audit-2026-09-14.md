# AutoPulse 日报完整性审计（2026-09-14）

## 结论

当前系统可以定时生成和发布日报，但不具备“全面覆盖重点品牌与行业动态”的能力。此前将构建成功、来源入口已登记和少量内容通过核验视为日报可用，是错误的验收标准。

## 当前证据

- 15 个重点品牌的官方微博均只能读取主页可见的 1—2 条内容，全部属于有限覆盖，不能证明全天帖子已读完。
- 16 个品牌官网或集团官网入口中，8 个仍待接入、1 个读取失败、1 个只能部分读取；“入口已登记”不等于“内容已采集”。
- 懂车帝目前只能提供公开首页标题，缺少可核验的发布时间与正文。
- 新浪、易车、IT之家等来源主要依赖 Bing 搜索结果页发现；搜索页返回 0 时，系统无法区分“当天无信息”和“搜索没有工作”。
- 微信公众号、品牌 App、抖音、小红书和今日头条尚未形成自动采集链路。
- 当前 124 条待核实线索中，68 条缺原文日期、38 条未读到正文、36 条官方帖子正文不完整。系统没有为这些线索自动寻找第二来源。
- 自动任务允许采集步骤失败后继续发布；覆盖严重不足时仍可能显示运行成功。
- 现有覆盖测试主要检查来源配置是否存在，没有检查当天是否成功读取、是否覆盖完整时间窗口以及是否形成可发布事件。

## 根因

1. **成功定义错误**：把“程序运行完成”当成“日报信息完整”。
2. **发现层过窄**：没有稳定的搜索 API 或数据服务，主要依赖网页列表和搜索结果页。
3. **官方信号不完整**：官网更新慢，微博主页存在登录、置顶和分页限制，微信公众号等关键渠道缺失。
4. **核验是单链接流程**：一个链接缺日期或正文就进入待核实，没有围绕同一事件跨来源补证。
5. **没有完整性门槛**：没有按品牌、渠道层、时间窗口和候选闭环率判断本期是否合格。
6. **没有异常反馈**：信息量异常偏低或来源大面积失效时，任务仍然成功，无法及时修复。

## 后续验收标准

每期日报发布前必须同时检查：

1. 15 个重点品牌均执行官网、官方自媒体和全网媒体检索；品牌别名与子品牌必须纳入查询。
2. 政策层至少检查工信部、国务院/国家部委和行业协会；市场层至少有三家可正常读取的垂直或财经媒体。
3. 采集窗口覆盖前一日 08:00 至当日 08:00，并在 08:00 后保留索引延迟补跑。
4. 对缺日期、缺正文和单一媒体线索，自动搜索同事件的官方或第二媒体来源。
5. 以来源健康度和候选闭环率判断完整性，不使用固定新闻条数凑数。
6. 关键渠道失效、重点品牌未完成检索或当日数量显著偏离近七日基线时，将本期标为覆盖不足并触发告警。
7. 自动任务只有在内容校验和覆盖校验都通过后，才标记为成功。

## 改造顺序

1. 重写覆盖检查与任务状态，先让系统能诚实识别“不完整”。
2. 接入稳定的搜索 API，并按品牌、别名、事件类型和两个自然日检索。
3. 补齐可直连的品牌官网、垂直媒体和政策列表源。
4. 建立事件级补证、合并和冲突处理，而不是按单个 URL 决定去留。
5. 接入官方公众号等高价值自媒体信号，微博登录态仅作为补充，不能作为唯一官方来源。
6. 用连续七天的人工基准日报测召回率，达到约定标准后再称为“自动完整日报”。
